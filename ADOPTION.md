# Adopt a reviewed revision

VERSION labels the candidate content. It is not an approval record. Select an
immutable commit whose exact content has completed the destination's permitted
formal review and landing process. A branch name or moving tag alone does not
identify that content.

1. Compare the selected practices with the project's canonical instructions and
   existing controls. Record applicable guidance and any project-owned exceptions.
2. Propose a small change to the project's entry instructions. Include the source
   URL, full commit ID and source-review record. Keep requirements, permissions,
   exceptions and enforcement definitions in the project.
3. Use the project's normal review and landing path. Record its adoption revision
   and any behavior or installation checks still needed. Selecting guidance does
   not install tools or alter provider settings.
4. Review a later handbook revision explicitly before changing the selection.
   Until then, the previous selection remains in effect.

An entry can follow this template; replace the placeholders before adoption:

```text
Handbook: https://github.com/porointern/agent-handbook/tree/<full-reviewed-commit>
Source review: <review record covering that exact content>
Use: delivery guidance; this project's instructions retain authority.
Exceptions and permissions: <project-owned record>
Adoption: <project review and landed revision>
```

Track source review, publication, profile linking, project adoption and actual
memory-disablement verification separately. Verify Claude and Codex effective
automatic-memory settings through existing project work; retain ordinary task
context and evidence. Neither an empty store nor a source merge is that proof.

If a destination has no permitted review path, retain the exact source and leave
publication pending until its owner selects an authorized path. Do not substitute
an informal model verdict or add a review workflow to manufacture approval.
